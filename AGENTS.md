# Agent guidance for repo.ing

For frontend design, UI review, visual polish, copy/layout work, or component restyling, use the repo-taste skill in .agents/skills/repo-taste/SKILL.md. Its portable principles, repo.ing profile and visual verification are under design/repo-taste/.

The project is a real financial application. Design work must preserve canonical repository identity, real chain-derived figures, fee/reward accounting, wallet prompts, slippage, signing, and trade/claim/launch safety checks. Do not modify transaction, settlement, custody, authorization, API, or production controls as part of a cosmetic task.

Use the existing stack, theme tokens, typography, and official brand assets. Keep working light/dark themes. Do not invent Repo Cat variants, claims of verified data, user balances, trading history, or proof.

For other engineering work, follow the relevant existing documentation and tests. This guidance does not authorize production deployment, main-branch merges, or onchain actions.
